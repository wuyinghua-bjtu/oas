2. 由于本人电脑配置一般(16GB内存,5个模拟器满载),所以部分延时写的挺长,可以根据情况酌情调整

### 现世协作

- 每轮扫描全部有效小号，打开详情确认现世类别并记录奖励、角色和区服。
- 现世协作只记录并在结束后推送，不挑选、不自动邀请，也不进入普通协作邀请或刷怪流程。
- 自动区分旧版与黑金版悬赏面板。旧版详情点击左下方空白处返回；黑金版点击详情自身的关闭按钮，避免误碰外层面板或现世入口。确认回到面板才继续扫描。
- 黑金版按四张可见卡片读取邀请入口和奖励，使用整行识别读取发现地点，好友必须有选中标记才确认邀请。规则只安装到寻找协作实例，不修改其他 OAS 配置的共享模板。
- 同一小号重复扫描时，复用按卡片位置、奖励和任务文字标识的普通/现世分类；内容改变后重新识别，避免反复打开详情触发连点保护。无法确认面板时保存现场并报识别失败，不当作没有协作。
- 寻找协作切号时单独识别登录页“切换”文字，最多点击三次，不再随机点击整条服务器名称区域；登录后仍核对角色名。设备窗口、进程和实例绑定保护保持启用。
- 勾协、狗粮和猫粮协作继续沿用原有邀请配置与邀请历史。
- 黑金面板邀请时核对好友全名和对应选中标记，单次点击黄色邀请按钮中心，连续两帧确认返回悬赏面板后才记录发送。按钮按下动画不作为发送成功；发送确认方式写入 JSON，仍不表示大号已接受。
- 已完成自己击杀进度的普通协作，即使详情不再显示“前往”，仍通过自己/好友进度区识别，正常返回面板。
- 小号成功发出普通协作邀请后，只追踪这些已分享的任务，完成小号自己的击杀进度后才切下一个号。大号不在可邀请列表时不启动该任务；打不过或进度识别异常则保留未完成状态与现场。
- 汇总分别显示“已发邀请”和“小号部分已完成”。中断后保留已追踪但未完成的状态，下次登录该小号先继续完成。
- 小号完成协作时，探索入口优先匹配图片，失败后识别“探索”文字；到达后同时确认探索页标志和底部入口，防止过渡画面误判。
- 探索到达确认同时检查底部御魂、觉醒入口和返回箭头，避免顶部欢迎提示遮住票券后误判。点击入口后等待动画，战斗返回也使用同一判断，仅影响寻找协作脚本。
- 完成计数支持斜杠被读成 7（例如 12712 表示 12/12），不会把“结界突破”等导航文字当成新悬赏。登录失效时只重试当前小号一次，再次失效则保留现场并停止，不跳过账号。
- 界面卡住或连续点击异常会立即停止并保留现场；其他可恢复错误在 10 分钟后重试。

### 协作记录与微信汇总

- 每轮重新扫描全部有效小号的协作任务，结束后汇总全部记录。现世任务始终只记录，不自动邀请。

- 自动记录已识别的勾协、狗粮协作、猫粮协作和现世协作，包含小号角色、区服、奖励、发现数量、邀请对象、邀请时间与失败原因。未邀请的任务也会记录。
- 邮箱登录的小号在汇总和记录中标注邮箱名前四位；不记录完整邮箱。手机账号不显示账号前缀。
- 同小号、同类别及奖励合并展示数量。重复识别不会累加数量；同一刷新时段重试会保留已有分享记录。
- “已分享”仅表示邀请操作成功结束，**不代表已确认大号接受邀请**。未扫描、识别失败的小号会单独列出，不会被当作没有协作。
- JSON 和 CSV 持续保存于 `log/FindJade/reports/<配置名>/`；`latest.json`、`latest.csv` 为最近一次结果，带时间的文件保留各轮结果，`period-*.json` 保存本刷新时段的累计记录。这些文件只包含角色和区服，不保存登录手机号、推送 Token。
- “结束后推送协作汇总”默认开启，使用该 OAS 配置“脚本 → 出错设置”中的推送通道。正常结束或异常结束都会提交汇总；内容较长时分段推送。推送失败仍保留本地完整记录。
