# 新号练级 SOP：实验切片

这是写入 OAS 脚本的确定性流程，不是让大模型看图后逐步操控游戏。
运行时由本地 OpenCV 模板、固定范围的 RuleOcr、状态策略和动作白名单执行；
不调用 LLM。当前接通初始庭院、树下剧情、小白/九命猫/神乐对话、阴阳眼开关提示、
两个镜头的显形问号控件和关闭阴阳眼后的狸猫入口的已采样画面，
**还不能全自动从 1 级练到 30 级**。

## 已验证与尚未接通的范围

- 已用三个真实截图验证初始庭院识别、账号 **3 级** OCR、角色名绑定 token，以及
  新手 NPC 头顶金环三点气泡。账号等级只读左上角账号徽章，不读时间、资源或式神等级。
- 可执行动作包括庭院/初始树下场景的 `story_npc`：账号与等级确认后，NPC 位置连续两帧稳定才点。
  召唤灯笼、任意白点、通用确认弹窗均不是可执行目标。
- 小白/九命猫/神乐对话仅点击已识别的“跳过”，阴阳眼提示仅点击金环白眼图标；
  两者都要求对应剧情场景锚点、无遮挡布局和连续两帧稳定，不能由通用按钮启用。
- 已知对白镜头中出现未校准角色名时，只有场景与对白控件均匹配才标记
  `story_dialogue_wait`。它只用于等待自行播放和确认转场，不提供跳过、返回或其他点击；
  仍受 `unknown_timeout_seconds` 限制，重复同一画面不会延长等待。
- “森林调查”动画使用标题、边框及播放/弹幕栏等 13 个静态锚点识别为
  `story_cinematic_wait`，不读弹幕内容、不触碰输入框/发送或未经确认的圆形跳过。
  整个被动动画等待段最多 90 秒；动画结束后普通未知页面另计原 30 秒，
  仍不能越过 90 秒总段限或 20 分钟会话限。只有实际执行白名单动作才重置该段计时。
- 动画后伞下 NPC 的新镜头使用独立背景/地面锚点和局部棕环三点控件，
  不降低旧镜头阈值，也不匹配整个人物姿态；此入口同样要求现场账号/等级和双帧确认。
- 显形剧情依靠场景锚点、纸符、人物选择性亮度，以及白色问号与棕色圆环共同确认。
  在已校准镜头的中央 NPC 区域查找唯一问号，位置连续两帧稳定才点击；
  返回庭院再进入会换镜头，不以旧 NPC 坐标判断剧情进度。
  同时有多个问号、缺失关键证据或明显弹层时不点击，不回退为固定坐标。
- 若从已支持的树下场景、对话、阴阳眼提示或显形场景重开任务，每种页面最多返回一次、
  每次运行合计最多返回两次，执行 `return_to_courtyard`：
  仅按已识别的返回按钮返回庭院，重新验证当前账号与等级，不能用旧断点代替核验。
- 运行中等级验证失效时，可通过已识别的返回按钮执行 `recheck_account`，
  清除本次身份/等级信任并重新双读；与初次返回共用上述次数限制。
  这不代表尚未实现的所有奖励节点已经能自动触发等级重检。
- 策略已有目标 30 级终止、等级重复确认、会话时限、账号绑定及体力预算保护。
  达到目标须由当前画面确认，不能仅凭旧断点判断完成；完成后会关闭该任务。
- **完整新手教程、后续剧情/主线、战斗与探索调度、账号经验及体力 OCR 尚未接通。**
  真实等级目前只校准了 3 级；30 级停止逻辑有策略测试，不等于已经实测完整升级。
- NPC 点击之后若出现未适配剧情，流程会保留证据并退出。这是当前支持边界，
  不会用通用“下一步/确认/自动战斗”循环代替缺失的教程规则。

角色名 OCR 是断点绑定 token，不是唯一账号 ID，也不是文字准确性保证。
当前样本存在“土/士”识别差异；脚本结合固定模拟器实例使用该 token，
不应把它当作经过验证的人物姓名。账号变化时必须重新确认现场状态。

## 固定使用第二台 MuMu

| 项目 | 必须使用的值 |
| --- | --- |
| 独立配置 | `config/oas_leveling.json`，配置名 `oas_leveling` |
| 窗口 | `MuMu安卓设备-1` |
| ADB 序列号 | `127.0.0.1:16416` |
| 实例名 | `MuMuPlayer-15.0-1` |
| 游戏包 | `com.netease.onmyoji` |
| 游戏原生画面 | **1280 × 720** |
| 截图 / 操作 | `window_background` / `window_message` |

运行器要求截图本身是原生 1280 × 720；离线测试里的尺寸归一化不代表运行器会缩放坐标。
实例绑定不符、共享队列开启，或此配置中有其他任务启用时，任务拒绝运行。
不使用或覆盖 `oas1`，也不自动切换到第一台 MuMu。
每次截图与点击前还会核对唯一精确窗口标题、根/渲染子窗口归属、进程名和
`--vm MuMuPlayer-15.0-1` 参数，以及实时 1280×720 客户区；窗口或进程在运行中
被替换时直接退出，不自动改绑。底层设备初始化仍连接第二台 ADB，
并非完全不使用 ADB；游戏内输入固定走 `window_message`。

## 启动与退出

1. 手动打开第二台 MuMu 并登录小号，登录、验证码、实名认证均由用户完成。
   确认游戏原生分辨率为 1280 × 720，先停在已支持的初始庭院或树下剧情页。
2. 在 OASX 选择 **`oas_leveling`**。这份配置只启用 `NewbieLeveling`，其他任务全部关闭，
   共享队列关闭；不要同时启动另一个控制同一台模拟器的进程。
3. 检查 `newbie_leveling.leveling_config`：`target_level=30`；
   `observe_only=true` 只观察，`false` 才允许执行已验证的剧情动作。
   `session_minutes` 限制单次运行时间，`unknown_timeout_seconds` 限制未知状态等待。
   `stamina_budget` 是后续战斗接口的保护条件，当前没有接入耗体力动作。
4. 启动所选配置。需要中止时使用 OASX 停止按钮；脚本不会自动启动模拟器、
   重新登录、切号、购买体力或执行付费操作。

未识别页面只会有限等待并退出；已发出动作但 12 秒内未验证页面转换时也会退出，
不会重复盲点。退出后先看证据，不要用反复重启绕过未知页面保护。
不要直接运行仓库的 `script.py` 入口来启动小号任务：该入口目前默认选择 `oas1`。

## 证据与断点

本任务的输出目录是 `log/newbie_leveling/oas_leveling/`：

- `checkpoint.json`：已绑定实例、角色名 token、确认等级与完成状态。重启后仍需现场确认。
- `status.json`：最近一次正常终止的 `completed` 或 `needs_attention`、原因与确认等级；
  它不是实时运行心跳，读取时同时检查时间戳。
- 时间戳 `.png` / `.json`：动作前、已确认的转换、暂停或完成证据。
  JSON 包含观察结果及会话/进度状态，可用来补后续确定性规则。
- 主日志可搜索 `LEVELING_START`、`LEVELING_DECISION`、`LEVELING_ACTION`、
  `LEVELING_EVIDENCE`、`LEVELING_PAUSED`、`LEVELING_COMPLETE`。
  现有日志器截断下划线后的配置名，所以主日志实际是 `log/YYYY-MM-DD_oas.txt`。

若发现账号或等级异常、断点损坏、未知页面，不手改断点伪造完成，也不删除证据后盲目继续。
截图可能包含角色信息，分享前按需遮挡。

## 后续 SOP 路线（规划，尚未全部实现）

先推进已经验证为 **0 体力** 的教程/剧情与解锁流程；遇到等级门槛才补账号经验。
只有现场确认活动/副本的免费条件、解锁条件与剩余次数后，才纳入免费经验路线；
不能假定存在 40 级大号、师傅或免费历练。
需要消耗体力时，先确认剩余体力与单次成本，在预算内刷已解锁、能稳定完成的经验怪，
逐场检查账号等级，接近 30 级时不再批量进入下一场。
账号经验与式神经验要分开记录；尚未实测的经验效率、所需体力与总时长不提供保证数字。

离线视觉回归：在 Backend 目录运行
`toolkit/python.exe -m unittest dev_tools.test_newbie_leveling_vision`。
如需同时使用已安装的本地 RuleOcr，先设置环境变量 `NEWBIE_VISION_REAL_OCR=1`。
这些测试只读截图，不连接或操作游戏。
